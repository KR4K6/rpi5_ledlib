# rpi5_ledlib

Python-библиотека для управления адресной LED-лентой **WS2812B** на **Raspberry Pi 5** с упором на **детерминированность** и предсказуемое поведение.

---

## Краткое описание

`rpi5_ledlib` решает задачу стабильной передачи данных в WS2812B на Raspberry Pi 5 через подход, совместимый с SPI-транспортом: данные для светодиодов сначала кодируются в последовательность бит, соответствующую временным требованиям WS2812B, после чего могут быть отправлены через интерфейс SPI.

---

## Проблематика

WS2812B критично зависит от точных таймингов сигнала. На Raspberry Pi 5 типовые подходы, которые хорошо работали на более ранних Raspberry Pi (PWM/DMA-пайплайны, битбангинг через GPIO и т.п.), на практике могут давать нестабильный результат:

- лента меняет состояние кратковременно и “отваливается”,
- после первого кадра перестаёт реагировать на обновления до остановки процесса,
- поведение зависит от нагрузки, планировщика, состояния системы.

Цель проекта — сделать передачу данных **воспроизводимой** и **предсказуемой**: чтобы одинаковый входной кадр давал одинаковый сигнал на выходе и одинаковую реакцию ленты.

## Как устроено

### 1) Encoder (ключевой компонент)

WS2812B принимает поток бит с очень строгими длительностями импульсов для “0” и “1”.  
Идея encoder’а: заменить “тайминги” на уровне GPIO на **кодирование каждого бита** в заранее определённую последовательность бит, которую затем можно передать по SPI с фиксированной частотой.

Используемая схема кодирования (3 SPI-бита на 1 исходный бит):

- `0 -> 100`
- `1 -> 110`

Порядок бит: **MSB first** (старший бит первым).

Следствие:
- 1 исходный байт (8 бит) превращается в 24 SPI-бита, то есть в **3 байта**.
- Любой исходный буфер длиной `N` байт превращается в `3N` байт на SPI.

В репозитории есть unit-тесты, которые проверяют:
- корректную длину результата,
- корректное кодирование на известных тест-векторах.

### 2) Уровень “лента” (логика формирования кадра)

В библиотеке есть слой, который отвечает за удобную работу с “пикселями” и формированием кадра (байтового массива цветов), который затем передаётся в encoder и ниже — в транспорт.

### 3) SPI-драйвер (транспорт)

SPI-драйвер — слой, который отвечает за фактическую отправку закодированного буфера. В тестах транспорт можно заменять мок-реализацией.

## Способы использования

Ниже — варианты установки/использования в зависимости от того, как вы хотите подключать библиотеку.

### Вариант A: клонирование репозитория и установка в editable-режиме (для разработки)

```bash
git clone https://github.com/KR4K6/rpi5_ledlib.git
cd rpi5_ledlib

python -m venv .venv
source .venv/bin/activate
python -m pip install -U pip

pip install -e .
```
### Вариант B: установка через pip из PyPI (когда проект будет опубликован)

```bash
pip install rpi5-ledlib
```
